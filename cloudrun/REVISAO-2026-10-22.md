## Budget e Spend Cap

Antes do deploy, configurar um budget mensal exclusivo de todos os servicos do
projeto, equivalente a US$5 na moeda da conta, alertas 50/80/100, e verificar os
destinatarios. O script de deploy agora consulta a API e recusa escopo de outro
projeto, moeda errada, valor superior ou alertas ausentes. Configure:

```bash
export AJEITA_BUDGET_AMOUNT=5
export AJEITA_BUDGET_CURRENCY=USD
# Somente se a conta for USD. Para BRL, definir equivalente aprovado em BRL.
bash cloudrun/verificar-orcamento.sh ajeita-seu-projeto
```

Spend Cap existe para Cloud Run (`152E-C115-5142`) na documentacao atual. Verificar
e criar no Console: Billing > Budgets & alerts > Create > Spend cap enforcement,
um unico projeto AJEITA e um unico servico Cloud Run. Recomenda-se valor abaixo
dos US$5 totais para reservar margem aos outros servicos. Nao transformar o budget
de todos os servicos em budget apenas Cloud Run. A conta precisa ser elegivel e
ter permissao para configurar cap; a disponibilidade nesta conta esta pendente.
O cap tem atraso, nao cobre outros servicos e reinicia no mes seguinte.

Fonte: https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps

## Operacao pelo celular

Use o Google Cloud Console no navegador, selecione somente o projeto AJEITA,
Cloud Run > ajeita-bot > Scaling > Manual: **0 para PARAR**, **1 para LIGAR**.
STATUS: verificar Conditions, instancias e `/pair` autenticado para estado real do
WhatsApp. EXCLUIR: excluir somente ajeita-bot apos confirmacao. Permanecem bucket,
Artifact Registry, secrets, logs e possivel armazenamento de builds, que exigem
revisao separada. Nao excluir objetos de sessao sem aceitar novo pareamento.

No Cloud Shell, os controles existentes aceitam `status|parar|ligar|apagar` e
`--execute`. Para teste com terminal aberto, usar `cloudrun/teste.sh`; solicita
parada em 30 minutos ou CTRL+C. Esse timer local nao e teto de faturamento e
nao sobrevive garantidamente a perda do terminal. Mantenha o Console acessivel.

## Pendencias obrigatorias antes de publicar

1. Configurar identidade Google segura no ambiente ou usar Cloud Shell autenticado.
   Nao colar codigos OAuth, tokens, arquivos de chave ou senhas na conversa.
2. Inventariar projetos/contas por leitura; criar projeto AJEITA e budget; validar
   moeda/destinatarios e Spend Cap. Registrar IDs de recursos novos.
3. Provisionar bucket privado em SP (sem versionamento/soft-delete prolongado
   desnecessario), runtime service account e segredo novos com permissoes minimas.
   IAM do runtime somente bucket e segredo do AJEITA; nao usar Owner/Editor.
4. Configurar limpeza das imagens antigas (preservando a atual), armazenamento de
   builds e retencao de logs. Nao ativar exports pagos ou load balancer/VPC extras.
5. Executar deploy desligado, validar max=1 e concorrencia=1 no Google Cloud.
   Cloud Run pode sobrepor instancias durante manutencao/deploy; limite configurado
   nao e trava distribuida de sessao. Parar e aguardar zero antes de redeploy.
6. Ligar janela curta, acessar `/pair` via HTTPS com admin/segredo novo, escanear
   QR e esperar primeiro backup. Testar os dois participantes e mensagem citada.
7. Parar, reiniciar brevemente e comprovar recuperacao sem QR; parar ao terminar.
   Verificar instancias zero e custos residuais. Nunca declarar esse teste aprovado
   com base apenas nos testes simulados.
